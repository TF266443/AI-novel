一、项目概述

项目名称（代号）：NovelMate —— 小说创作深度伴侣

一句话定位：面向严肃作者的"私人创作顾问"，把任意小说从骨架→血肉→呼吸→灵魂逐层拆解，并以可被引用、可被检验的方式辅助扩写、续写、仿写，同时在创作过程中实时防止 OOC（角色脱离设定）。

设计原则：
1. 言之有据：所有 AI 输出必须可追溯到原文片段或用户档案条款（Citation-first）。
2. 结构化优先：解构结果一律以受约束 JSON 落库，前端可编辑、可版本化、可回滚。
3. 提示词与代码解耦：所有提示词（含扩写、续写、仿写、审查）由用户以 JSON 文件上传，热加载，无需发版。
4. 人在回路：AI 给建议、不直接覆盖正文；用户保留最终决策权。
5. 可替换的模型层：上层流程不绑定具体厂商，便于在 Claude / GPT / 本地模型之间切换或路由。

三、技术架构

采用"轻量级全栈 + 可替换模型层"架构，平衡开发成本、可观测性与扩展性。

```
┌──────────────────────────────────────────────┐
│              前端 (Web)                       │
│  React + Tailwind + TipTap (编辑器)           │
│  D3.js (关系图) · Zustand (状态)              │
│  SSE/WebSocket 流式接收                       │
└──────────────────────┬───────────────────────┘
                       │ HTTPS / WSS
┌──────────────────────▼───────────────────────┐
│           应用层 (Python FastAPI)             │
│  · 文件解析 / 切片                            │
│  · 解构任务调度 (Celery + Redis)              │
│  · 创作会话管理                               │
│  · 提示词加载器 (JSON 热加载 + Jinja 渲染)    │
│  · LLM 网关 (路由 / 限流 / 重试 / 缓存)       │
│  · RAG 检索服务 (混合检索 + Rerank)           │
│  · 观测 (OpenTelemetry + Prom)                │
└──────────────────────┬───────────────────────┘
        ┌──────────────┼───────────────┐
        ▼              ▼               ▼
   ┌─────────┐   ┌─────────┐    ┌──────────────┐
   │PostgreSQL│  │ 向量库   │    │  LLM 提供商   │
   │结构化数据 │  │ Qdrant/  │    │ Claude / GPT  │
   │+ pgvector│  │ Milvus  │    │ / 本地 vLLM   │
   └─────────┘   └─────────┘    └──────────────┘
        │
        ▼
   ┌─────────┐
   │ 对象存储 │ (原始文件、长任务报告、提示词包归档)
   │  S3/MinIO│
   └─────────┘
```

技术选型说明：

- 前端：React + Tailwind CSS；TipTap 作为正文编辑器（基于 ProseMirror，便于自定义 OOC 高亮、修改建议气泡、内联引用 Mark）；D3.js 实现关系图；状态层用 Zustand，避免过早引入 Redux。
- 后端：Python 3.11 + FastAPI（异步 IO，与流式 LLM 调用契合）；Celery + Redis 处理长任务（解构、全文审计）。
- LLM 网关：自建薄层，向上暴露统一接口，向下适配多家厂商；支持模型路由（按任务难度选模型）、Token 预算、指数退避重试、结果缓存（按 prompt+model+params 哈希）。
- RAG：向量库可选 Qdrant（自托管简单）或 Milvus；嵌入模型默认 bge-m3 或 OpenAI text-embedding-3-large；检索采用 BM25 + 向量混合，召回后由 Cohere Rerank（或开源 bge-reranker）二次排序。MVP 阶段可仅用 PostgreSQL + pgvector，避免引入额外组件。
- 数据存储：PostgreSQL 存项目、角色、规则、事件、审计、版本；pgvector 存切片向量（如未引入独立向量库）。
- 文件解析：PyMuPDF（PDF）、ebooklib（EPUB）、python-docx（DOCX）、markdown-it-py（MD）、纯文本直读；统一中间表示为"章节 → 段落 → 句"的层级 AST，保留原始偏移用于精确引用。

四、模块详细设计

1. 作品上传与解析模块

- 上传走预签名直传（避免大文件经过 API）。
- 解析流程：格式探测 → 文本抽取 → 章节识别（规则 + LLM 兜底）→ 段落切片 → 句级偏移记录。
- 切片策略：基于句子边界的滑动窗口，目标 800~1200 tokens / 片，重叠 ~15%；保留 {book_id, chapter_id, paragraph_id, char_offset_start/end}。
- 嵌入入库：批量调用嵌入接口，写入向量库；同时在 Postgres 写入切片正文与元数据，便于全文检索与精确引用。
- 输出全文目录树，前端可点击导航。

2. 智能解构引擎（核心）

通过分步提示词链模拟编辑提炼流程，每一步均强约束 JSON 输出，失败自动重试 / 降级。

工作流：

(1) 世界观与规则提取
- 通过 RAG 选取设定密集段落（地理、制度、超自然规则的首次出现处）。
- 输出 schema：{时空背景, 地理, 社会结构, 权力体系, 超自然/科技规则[], 经济/语言/宗教, 隐性禁忌}。

(2) 人物档案建立
- 先做"人物候选发现"（NER + 共指消解 + LLM 复核），按出场频次与剧情权重排序。
- 对每个重要人物：滚动喂入其代表性出场段落（RAG 召回 + 关键节点抽样），输出：
  · 姓名 / 别名 / 称谓
  · 欲求（显性 + 隐性）
  · 恐惧
  · 声音指纹：口头禅 [], 句式模板 [], 偏好词 [], 禁用词 [], 语域（书面/口语/粗粝/雅致）
  · 隐秘伤口（含触发条件与反应模式）
  · 人物弧光：起点态 → 关键转折事件 [] → 终点态
  · 关系网快照（指向其他角色 ID）

(3) 情节因果链
- 抽取关键事件，结构化为有向图节点：{id, chapter_anchor, summary, cause_ids[], effect_ids[], stakes, foreshadow_payoff_pair}。
- 同步标记"未爆弹"（埋而未爆）与"已引爆点"，用于后续防 OOC 与审计。

(4) 风格指纹提取
- 选取 10~15 个代表性段落（覆盖叙述、对话、动作、心理、景物）。
- 量化维度：平均句长、句长方差、对话占比、修饰密度、视角与叙事距离、修辞偏好、语域、典型节奏型。
- 产出"仿写转换规则"+ 3~5 对少样本（普通句 → 风格句），用于后续仿写 Prompt 注入。

(5) 灵感卡生成
- 输入：人物档案 + 因果链 + 未爆弹 + 留白点。
- 输出 5~10 张灵感卡：{起爆点, 涉及角色, 预期冲突, 风险, 与主线的耦合度评分}。

所有解构结果以 JSON 落 Postgres，关联 book_id 与 version；前端提供可视化编辑器，用户修订视为"作者裁决"，优先级高于 AI 原始输出。

3. 创作辅助模块（接入用户上传的 JSON 提示词包）

- 仿写：选中正文片段 → 选择仿写目标风格指纹 → 系统组合"原句 + 风格规则 + 少样本 + 用户提示词包"调用 LLM，返回 3 个候选。
- 续写：光标停驻处取上下文（前 N 段，按 token 预算动态截断）+ 涉及角色档案 + 当前未爆弹状态 + 用户上传的续写提示词 → 返回 3 条不同走向，每条附"基调标签 / 风险标签"。
- 文风一致性监控：段落落定时异步计算与目标风格指纹的相似度，超阈值时在编辑器边栏给出偏离提示与可点击的修正建议。

4. 防 OOC 实时审查器

独立的"审查智能体"，与正文写作流解耦，避免相互污染上下文。

- 触发：自然段落定 / 手动触发 / 整段粘贴时自动触发。
- 打包上下文：当前段落 + 涉及角色"角色圣经"完整切面 + 场景上下文（前若干段）+ 世界观规则相关条款（RAG 召回）。
- 审查 Rubric：
  · 对话是否符合声音指纹（口头禅、句式、禁用词）
  · 关键动作是否与欲求 / 恐惧自洽
  · 是否触碰隐秘伤口，若触碰，反应是否合规
  · 是否违反世界观规则
  · 是否破坏人物弧光节奏（如关键弧光未铺垫即跳跃）
- 输出 JSON：{verdict: PASS|WARN|FAIL, items:[{rule_id, severity, evidence_quote, source_ref, suggested_direction}]}。审查器只给方向，不直接改写。
- 落库：所有审查记录入 ooc_audits 表，支持回看与"作者已采纳 / 已驳回"标记，作为后续提示词调优数据。

5. 回溯一致性审计模块

异步长任务（Celery），适合长篇完成后或大改后跑。

- 任务分片：按章节切片，并行调用；末端汇总聚合。
- 检查项：弧光倒退、关系网互动异常（如人物 A、B 在某章关系态与档案矛盾）、时间线冲突、规则违反、未爆弹提前 / 失踪、风格漂移。
- 输出：分级问题报告（CRITICAL / HIGH / MEDIUM / LOW）+ 精确定位（章节 / 段落偏移）+ 引用证据 + 建议处理。
- 报告归档至对象存储，前端可在"审计中心"分页浏览与跳转修复。

6. 提示词包管理模块（适配"用户上传 JSON 提示词文件"的需求）

设计目标：提示词与代码完全解耦；用户/团队可上传任意结构的 JSON 文件作为提示词包，热加载后即生效，无需重启服务。

- 上传与存储：JSON 文件原样存入对象存储；元数据（名称、用途分类、版本、上传者、上传时间、SHA256）入 Postgres。
- 结构不约束：系统不强求字段名；但提供推荐模板（可选填）：
  ```json
  {
    "name": "扩写_细腻心理流",
    "purpose": "expansion",        // 用途标签（自由文本），如 expansion/continuation/imitation/ooc/decompose
    "model_hint": "claude-opus",   // 可选：偏好模型
    "params": { "temperature": 0.8, "top_p": 0.9 },
    "system": "你是……",
    "user_template": "原文：{{source}}\n人物档案：{{character_bible}}\n要求：……",
    "fewshot": [ {"input": "...", "output": "..."} ],
    "post_validators": ["json_schema:expansion_v1"]   // 可选：输出校验
  }
  ```
- 变量插值：使用 Jinja2 渲染 user_template；系统在调用时按当前任务上下文自动注入可用变量（source / character_bible / world_rules / recent_context / style_fingerprint / cards 等），未被模板使用的变量自动忽略。
- 字段宽松匹配：加载器对常见同义字段做兼容（system / system_prompt / instructions；user_template / template / prompt；fewshot / examples / shots），降低上传门槛。
- 选用策略：
  · 用户在创作面板可显式选择某个提示词包；
  · 也可设置默认包（按用途分类）；
  · 同名包按"版本"灰度，可 A/B。
- 版本与回滚：每次上传同名包视为新版本；可一键回滚；保留 diff 视图。
- 安全：渲染前对模板做沙箱限制（禁用文件、环境、网络相关过滤器）；对超长提示词与潜在注入字段做长度与字符白名单检查；标记"含外部链接 / 含越权指令"风险，需用户在 UI 中显式确认。

六、提示词工程策略

- 系统提示词模板化：解构师、风格分析师、审查员、续写顾问、灵感生成器等角色分别有独立系统提示词，存为可热加载的 JSON 提示词包。
- 强约束输出：要求 JSON 时优先使用厂商的 JSON Mode / Tool Use；失败时进入"格式修复链"（让小模型把脏输出修成合法 JSON），再失败则降级为 Markdown 并标记 degraded=true。
- 少样本嵌入：风格仿写、声音指纹等任务在 Prompt 内固定放入 3~5 个原作典型样本。
- 动态上下文组装：基于当前操作触发 RAG 检索 → 重排序 → Token 预算下截断 → 注入模板。
- 引用强制：要求模型在引用原文时必须给出 {chunk_id, char_start, char_end}；后端二次校验，未提供或不存在的引用一律拒绝并重试。

七、可观测、成本与可靠性

- 链路追踪：每一次 LLM 调用都关联 trace_id（OpenTelemetry），含提示词包版本、模型、参数、Token、耗时、命中缓存与否。
- 成本面板：按项目 / 用户 / 模块聚合 Token 与费用；可设月度上限并在达阈值前预警。
- 缓存：按 (prompt_pack_version + rendered_input_hash + model + params) 作为 key 做语义不敏感缓存；解构、关系图等高确定性任务收益尤大。
- 限流与隔离：每个用户独立速率桶；长任务与交互任务走不同 Celery 队列，避免相互拖慢。
- 失败处理：所有外部调用包裹重试 + 指数退避 + 熔断；持久化失败任务进入"待人工复核"队列。
- 流式输出：续写、仿写、解构报告均通过 SSE 流式回传，提升体感。

---

八、安全与隐私

- 数据所有权：用户上传作品默认私有；未经显式许可不得用于模型训练或跨用户检索。
- 提示词包注入防护：渲染前过滤潜在的指令越权片段（如尝试覆盖系统指令、要求模型忽略安全策略），并对此类内容做风险标记。
- 行业合规：完整审计日志（谁、何时、对哪份作品做了什么 AI 调用）；支持数据导出与删除（GDPR / 个保法）。
- 密钥管理：LLM API Key 一律走密钥管理（KMS 或 Vault），不进代码、不进日志。

---

九、评测与质量度量

为避免"看起来不错就上线"，建立可量化的评测集：

- 黄金集：精选 10 部不同风格作品，人工标注其世界观规则、角色档案要点、典型 OOC 反例，作为回归基准。
- 解构准确率：与黄金集对比的字段级 F1。
- 风格一致性：仿写输出与目标风格指纹的相似度（句法 + 词法 + 语义多通道）。
- OOC 召回率 / 误报率：在人工标注的 OOC 反例集上跑审查器，要求误报率 < 阈值。
- 引用真实性：抽样核对模型给出的引用是否能在原文精确命中。
- 用户主观评分：在产品内嵌入"该建议有用 / 一般 / 无用"快捷反馈，作为离线再训练与提示词调优数据源。

每次提示词包升级、模型替换都必须跑回归集，结果记录于"模型变更日志"。

十、开发分期与迭代计划

第一阶段 · MVP（4~6 周）
目标：验证"解构 + 灵感 + 用户自带提示词"的核心价值。
- 文件上传与解析（PDF / EPUB / TXT）。
- 四维解构（结果以结构化 JSON 落库，前端可读可改）。
- 续写、扩写、仿写基础流程，提示词全部从用户上传的 JSON 包加载。
- 文库管理、解构报告查看、TipTap 编辑器。
- LLM 网关 + 调用计费可视化。
- 暂不上：实时 OOC、向量库（用全文摘要 + 直接上下文注入）、关系图。

第二阶段 · 一致性增强版（追加 8~12 周）
目标：建立专业壁垒。
- 引入向量库 + 混合检索 + Rerank，所有解构与审查均带证据引用。
- 实时防 OOC 审查器（独立面板 + 自动 / 手动触发）。
- 角色关系图可视化，支持手动编辑与版本回滚。
- 文风一致性监控与回溯审计（异步报告）。
- 提示词包版本化、灰度与 A/B。
- 评测黄金集与回归流水线接入 CI。

第三阶段 · 个性化与高级功能（长期）
- 用户私人风格微调：LoRA / DPO，以作者自身历史作品定制"以我之声续写"。
- 多智能体协作可视化：解构 / 审查 / 灵感智能体的思考链以可读形式呈现。
- 团队协作、变更评审与版本对比。
- 大师思维模式包（海明威 / 金庸 / 卡佛 …）以提示词包形式发行。

---

十一、主要风险与缓解

- LLM 幻觉与误判 → 引用强制 + 二次校验 + 用户最终决策；OOC 审查只提示不改写。
- 长篇上下文超限 → RAG + 分段总结 + 角色档案的"切面注入"（只拿与当前段落相关的字段）。
- 成本失控 → 任务分级路由（重任务 Opus / 轻任务 Haiku 或本地模型）+ 缓存 + 配额。
- 提示词包恶意注入 → 沙箱渲染 + 风险标记 + 显式确认。
- 版权与隐私 → 默认私有、最小化训练使用、合规导出删除。
- 评测漂移 → 黄金集 + 每次变更跑回归 + 变更日志可审计。

---

十二、面向用户的提示词包上传 UX 要点

- 上传入口：设置 → 提示词管理 → "上传 JSON"；可拖拽多文件。
- 解析反馈：上传后立刻显示解析结果（识别到的用途、模型偏好、变量占位符、未识别字段），让用户能立刻看到"系统怎么理解这份提示词"。
- 试跑（Dry Run）：在不真正生成正文的前提下，预览模板渲染后的最终提示词（含变量填充），便于排错。
- 绑定：把提示词包绑定到具体的"动作按钮"（扩写 / 续写 / 仿写 / OOC / 自定义动作）；可对同一动作配置多个包并设默认。
- 分享与导入：支持以单 JSON 文件导出 / 导入提示词包，便于在社区与团队之间流通。
